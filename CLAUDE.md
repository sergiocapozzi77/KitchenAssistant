## Project Overview

KitchenAssistant is an ESP32-P4 embedded application for kitchen inventory management. It tracks products and expiry dates via Appwrite cloud, and suggests recipes from GoodFood based on available ingredients. The UI runs on an 800x1280 LCD using LVGL 9.x.

## Build Commands

Requires ESP-IDF v5.5.2 installed at `C:\Users\sergi\esp\v5.5.2\esp-idf`.

```bash
idf.py set-target esp32p4   # one-time setup
idf.py build
idf.py -p COM10 flash
idf.py -p COM10 monitor
idf.py -p COM10 flash monitor  # flash and immediately monitor
idf.py fullclean              # clean all build artifacts
```

WiFi credentials and other settings are configured via:

```bash
idf.py menuconfig  # look under "Kitchen Assistant Configuration"
```

## Architecture

### Layer Stack

```
LVGL UI (EEZ Studio generated: main/ui/)
    ↕
UI Extensions (main/ui_extensions.cpp) — populates LVGL widgets from data
    ↕
Services (ProductService, RecipeGoodFoodService, WiFiManager)
    ↕
ESP-IDF HTTP client + cJSON + FreeRTOS
```

### Key Components

**`main/app.cpp`** — Initialization pipeline and main loop:

1. `initNVS()` → NVS storage
2. `initHardware()` → WiFi, display, LVGL port
3. `initTasks()` → spawns `fetchProductsTask` FreeRTOS background task
4. `mainLoop()` → LVGL tick at ~100Hz

**`main/ProductService.cpp`** — Appwrite Cloud client (fra.cloud.appwrite.io). Queries products expiring today/tomorrow, supports full CRUD. Uses `esp_http_client` and `cJSON`. API key lives in `main/secrets.h` (not committed).

**`main/ProductsManager.cpp`** — Mutex-protected in-memory cache of products. Background task writes here; LVGL tick reads here.

**`main/RecipeGoodFoodService.cpp`** — Fetches recipe suggestions from GoodFood. Parses HTML responses.

**`main/ui_extensions.cpp`** — Bridges data layer to LVGL. `populateProductList()` and `populateRecipeList()` build card widgets, expiry badges, quantity controls, and fetch JPEG thumbnails (limited to 2 concurrent fetches via semaphore).

**`main/ui/`** — Generated by EEZ Studio. Do not manually edit `screens.c`, `styles.c`, `images.c`. Edit `actions.cpp` for event handlers — it's the designated manual-edit file in EEZ's workflow.

### Concurrency Model

- `fetchProductsTask` (FreeRTOS task): waits for WiFi + SNTP sync, then fetches from Appwrite. Writes to `ProductsManager` under mutex.
- LVGL main loop runs on the main task at 100Hz. Reads from `ProductsManager` under mutex.
- Thumbnail downloads use a semaphore to cap at 2 concurrent HTTP requests.

### Flash Partitions (`partitions.csv`)

| Name    | Size | Purpose            |
| ------- | ---- | ------------------ |
| NVS     | 24KB | Key-value storage  |
| factory | 8MB  | Application binary |
| storage | 7MB  | SPIFFS filesystem  |

### Managed vs Local Components

- **`managed_components/`** — auto-downloaded from ESP Component Registry (declared in `main/idf_component.yml`, pinned in `dependencies.lock`). Do not edit manually.
- **`components/`** — local custom drivers (BSP, LCD JD9365, touchscreen GSL3680). These are editable.
